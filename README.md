# 水电煤气管理系统

## 项目简介

本项目是一个基于 C++ 控制台的水电煤气管理系统，主要用于模拟高校或宿舍场景下的水费、电费、煤气费管理流程。系统支持用户信息录入、收费标准设置、抄表数据录入、费用计算、个人信息查询以及欠费情况查询等功能。

项目设计时区分了教师用户和学生用户两类对象。教师按照基础单价全额计费，学生具有一定免费额度，超出免费额度后再按照学生收费标准进行计费。该设计体现了 C++ 面向对象程序设计中的类、对象、继承、派生、组合等思想。

> 说明：本项目为合肥工业大学（HFUT）《程序设计基础》课程期末实训 / 课程作业项目，仅用于课程学习、程序设计训练与交流参考。

1. **数据持久化功能尚未完成**
   - 当前用户信息、抄表数据、缴费数据主要保存在程序运行期间的数组中。
   - 程序关闭后，运行中输入的数据不会自动保存。
   - 后续可以增加文件读写功能，例如使用 `.txt`、`.csv` 或二进制文件保存用户数据。

2. **历史缴费记录功能仍可继续完善**

   - 后续可以增加更严格的输入校验和错误恢复机制。

4. **用户数据容量仍可优化**

5. **菜单和业务逻辑仍可拆分**
   - 当前主函数承担了较多菜单控制和业务调度任务。
   - 后续可以将管理员菜单、教师菜单、学生菜单、查询模块、缴费模块等拆分为独立函数或独立类。

6. **图形界面或 Web 页面未实现**

## 功能说明

本系统主要实现以下功能：

1. **用户信息管理**
   - 添加教师用户信息
   - 添加学生用户信息
   - 记录用户姓名、水卡号、电卡号、煤气卡号等基础信息

2. **收费标准管理**
   - 设置教师水费、电费、煤气费单价
   - 设置学生水费、电费、煤气费单价
   - 设置学生水、电、煤气免费额度

3. **抄表数据录入**
   - 按姓名录入水、电、煤气当前读数
   - 按水卡号录入水表读数
   - 按电卡号录入电表读数
   - 按煤气卡号录入煤气表读数

4. **费用计算**
   - 自动计算本次水费、电费、煤气费
   - 自动统计当前累计应缴费用
   - 自动判断当前账户余额或欠费金额

5. **信息查询**
   - 查询当前收费标准
   - 查询全部学生信息
   - 查询全部教师信息
   - 按姓名查询个人信息
   - 按卡号查询个人信息

6. **缴费功能**
   - 教师和学生用户均可进行充值缴费
   - 系统根据已缴金额和应缴金额计算余额或欠费情况

## 类与对象关系说明

本项目采用面向对象思想设计，主要类之间关系如下。

### 1. `person` 基类

`person` 是用户基础类，用于保存所有用户共有的基础信息。

主要属性包括：

| 属性名           | 含义         |
| ---------------- | ------------ |
| `name`           | 姓名         |
| `water_id`       | 水卡号       |
| `electricity_id` | 电卡号       |
| `gas_id`         | 煤气卡号     |
| `paid_price`     | 当前已缴金额 |

主要方法包括：

| 方法名                | 功能             |
| --------------------- | ---------------- |
| `changeperson()`      | 修改用户基础信息 |
| `getname()`           | 获取姓名         |
| `getwater_id()`       | 获取水卡号       |
| `getelectricity_id()` | 获取电卡号       |
| `getgas_id()`         | 获取煤气卡号     |
| `pay()`               | 缴费             |
| `getPaidPrice()`      | 获取已缴金额     |
| `setPaidPrice()`      | 设置已缴金额     |

### 2. `teacher` 和 `student` 派生类

`teacher` 和 `student` 都继承自 `person` 类。

```text
person
├── teacher
└── student
```

二者都具有姓名、水卡号、电卡号、煤气卡号、已缴金额等基础信息，但在系统中的计费规则不同：

| 类名      | 说明                                             |
| --------- | ------------------------------------------------ |
| `teacher` | 教师用户类，教师按照普通单价全额收费             |
| `student` | 学生用户类，学生具有免费额度，超出免费额度后收费 |

### 6. `studentinformation` 学生信息类

`studentinformation` 同时继承：

- `information`
- `guidelineofstudent`
- `student`

```text
studentinformation
├── information
├── guidelineofstudent
└── student
```

该类表示一个完整的学生水电煤气账户对象。它既包含学生基础信息，又包含学生收费标准，还包含学生抄表信息，可以独立完成学生用户的费用计算、信息输出、充值和欠费判断。

学生费用计算规则：

```text
应收费用量 = max(0, 当前读数 - 免费额度)
应缴费用 = 应收费用量 × 学生单价
```

例如，学生免费水额度为 10 吨，如果当前水表读数为 15 吨，则只对超出的 5 吨进行收费。

### 7. `teacherinformation` 教师信息类

- `teacher`

```text
teacherinformation

```

该类表示一个完整的教师水电煤气账户对象。它既包含教师基础信息，又包含教师收费标准，还包含教师抄表信息，可以独立完成教师用户的费用计算、信息输出、充值和欠费判断。

教师费用计算规则：

```text
应缴费用 = 实际使用量 × 教师单价
```

## 系统整体设计思路

系统整体上分为四个核心模块：

| 模块         | 对应类                                                  | 功能                             |
| ------------ | ------------------------------------------------------- | -------------------------------- |
| 用户管理模块 | `person`、`teacher`、`student`                          | 保存用户基础信息                 |
| 收费标准模块 | `guideline`、`guidelineofteacher`、`guidelineofstudent` | 保存教师和学生的收费规则         |
| 抄表信息模块 | `information`                                           | 保存水、电、煤气读数和抄表时间   |
| 综合业务模块 | `teacherinformation`、`studentinformation`              | 计算费用、判断欠费、输出完整信息 |

系统通过 `main.cpp` 中的菜单实现功能调度。用户进入程序后，可以选择身份：

```text
1 - 管理人员
2 - 老师
3 - 学生
```

不同身份拥有不同权限：

| 身份     | 可用功能                                         |
| -------- | ------------------------------------------------ |
| 管理人员 | 添加成员、设置价格、查询信息、录入抄表数据       |
| 教师     | 注册、登录、缴费、查询个人信息、自行录入抄表信息 |
| 学生     | 注册、登录、缴费、查询个人信息、自行录入抄表信息 |

## 命名风格说明

本项目变量和函数命名主要遵循以下规则：

1. **类名使用小写英文**
   - 例如：`person`、`teacher`、`student`、`information`、`guideline`

2. **变量名使用英文含义命名**
   - 例如：`water_price` 表示水费单价
   - 例如：`gas_id` 表示煤气卡号

3. **多个单词之间使用下划线连接**
   - 例如：`electricity_price`
   - 例如：`nowtime_waterusing`

4. **函数名尽量体现动作**
   - `change...` 表示修改信息
   - `get...` 表示获取信息
   - `print()` 表示输出信息
   - `paid()` 或 `pay()` 表示缴费
   - `usingnewguideline()` 表示使用新的收费标准重新计算费用

5. **对象名尽量简短但保留含义**
   - `stu` 表示学生对象数组
   - `tea` 表示教师对象数组
   - `guidelinestudent` 表示学生收费标准对象
   - `guidelineteacher` 表示教师收费标准对象

## 程序使用说明

程序运行后，首先选择身份：

```text
请选择你的身份（1-管理人员、2-老师、3-学生）：
```

### 管理人员功能

管理人员可以执行以下操作：

```text
1 - 添加成员
2 - 价格填写
3 - 信息查询
4 - 抄表信息录入
```

#### 添加成员

输入教师数量和学生数量，然后按提示依次输入用户信息。

输入格式示例：

```text
2 2
张老师
1001 2001 3001
李老师
1002 2002 3002
张三
1101 2101 3101
李四
1102 2102 3102
```

#### 价格填写

先输入教师水、电、煤气单价：

```text
2.5 0.6 3.0
```

再输入学生水、电、煤气单价：

```text
3.0 0.8 3.5
```

最后输入学生水、电、煤气免费额度：

```text
3 10 5
```

#### 信息查询

可查询：

```text
1 - 当前价格
2 - 学生信息查询
3 - 教师信息查询
```


## 设计特点

### 1. 使用继承减少重复代码

教师和学生都拥有姓名、卡号、缴费金额等共有信息，因此使用 `person` 作为基类，将共有属性和方法统一管理。

### 2. 区分教师和学生收费逻辑

教师没有免费额度，费用直接按照实际用量计算。

学生拥有免费额度，只有超过免费额度的部分才收费。

### 3. 使用综合信息类整合业务

`teacherinformation` 和 `studentinformation` 通过多重继承整合用户信息、收费标准和抄表信息，使一个对象可以完成完整的业务操作。

### 4. 支持多种查询方式

系统既可以按姓名查询，也可以按水卡号、电卡号、煤气卡号查询，方便模拟实际管理场景。

### 5. 支持账户余额和欠费判断

系统会根据累计应缴费用和已缴金额计算余额。当余额为负数时，表示用户已经欠费。

## 当前不足与可改进方向

本项目主要用于课程设计和 C++ 基础训练，因此仍有一些可以改进的地方：

1. **数据未持久化**
   - 当前数据主要保存在程序运行时的数组中，程序关闭后数据会丢失。
   - 后续可以加入文件读写或数据库保存功能。

2. **数组容量固定**
   - 当前使用固定大小数组保存用户对象。
   - 后续可以改为动态数组、链表或 `vector` 等容器。

3. **输入容错性有限**
   - 如果用户输入格式错误，可能影响后续运行。
   - 后续可以增加输入合法性检查。

4. **菜单结构较长**
   - 主函数中菜单逻辑较多。
   - 后续可以进一步拆分为多个函数，提高代码可读性。

5. **界面较简单**
   - 当前为控制台交互。
   - 后续可以尝试加入图形界面或 Web 页面。

6. **命名仍可进一步规范**
   - 例如 `surpuls` 可以改为 `surplus`。
   - 部分函数名可以进一步统一为更规范的英文命名方式。
